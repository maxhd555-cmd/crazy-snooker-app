# รายการตรวจสอบระบบแบบไล่ทีละเมนู

เอกสารนี้ใช้ตรวจรับระบบในสภาพแวดล้อมทดสอบ โดยข้อมูลที่สร้างระหว่างการทดสอบต้องคืนสภาพก่อนจบทุกเมนู และการส่ง LINE จริงจะไม่ถูกเรียกซ้ำ เว้นแต่ได้รับการยืนยันเฉพาะจากผู้ดูแลแล้ว

| ลำดับ | เมนู | สิ่งที่ตรวจ | เกณฑ์ผ่าน | ขอบเขตพิเศษ |
| ---: | --- | --- | --- | --- |
| 1 | จุดขาย POS | เลือกสินค้า, เพิ่ม/ลดจำนวน, ค้นหาบาร์โค้ด, กล้อง, สร้าง QR | ตะกร้าและยอดรวมถูกต้อง; validation และ readiness แสดงชัด | QR ร้านจริงรอ PromptPay recipient |
| 2 | สมาชิกและ Wallet | เลือกสมาชิก, เปลี่ยนยอดเติม, สร้าง QR | ค่าที่เลือกสะท้อนใน UI; readiness ป้องกันธุรกรรมจริงเมื่อยังไม่ตั้งค่า | ทดสอบวงจร QR ใน process แยก |
| 3 | จองโต๊ะและแจ้งเตือน | validation ฟอร์ม, บันทึกการจอง, ปุ่ม near-end | กรอกไม่ครบถูกบล็อก; UI แสดงผล API ชัด | การส่ง LINE จริงผ่านการยืนยันแยกแล้ว |
| 4 | คลังและบาร์โค้ด | ค้นหารหัส, รับเข้า, ปรับออก, กล้อง | สต็อกเปลี่ยนตามการกระทำและคืนสภาพได้ | กล้องตรวจเส้นทาง error หากไม่มีสิทธิ์/อุปกรณ์ |
| 5 | สถานะโต๊ะ | เปลี่ยนทุกสถานะ, เวลาเลิกเล่น, ป้ายเวลา | UI อัปเดตทันที, SSE ซิงก์, โต๊ะทดสอบคืนค่าเดิม | ใช้โต๊ะ 02 สำหรับ test และคืนเป็น available |
| 6 | ประวัติรายการ | filters, ล้าง filters, เปิดใบเสร็จ, สรุปกะ | รายการและยอดสรุปเปลี่ยนตาม filter | การพิมพ์ถูก mock ใน browser test |
| 7 | การตั้งค่า | คู่มือ, PDF, ทัวร์ใหม่, readiness refresh | เปิด/ดาวน์โหลด/รีสตาร์ตได้; readiness ไม่เปิดเผยข้อมูลลับ | ไม่ต้องใช้ credential เพื่อแสดงสถานะ |
| 8 | รายงานผู้ใช้ | รหัสแอดมิน, filters, refresh, รายละเอียด, note, สถานะ | รหัสผิดถูกปฏิเสธ; note/status คงอยู่และรายงาน test ถูกปิด | ใช้ report `[TEST]` และเปลี่ยนเป็น resolved |

## ลำดับการรันทดสอบ

เริ่มจาก `pnpm test` และ `pnpm build` จากนั้นรันสคริปต์ตามเมนู: `verify-all-controls.mjs`, `verify-table-ui.mjs`, `verify-feedback-ui.mjs`, `verify-receipt-controls.mjs`, `verify-integration-readiness-ui.mjs`, และ `verify-shift-summary-ui.mjs` ส่วน `verify-payment-lifecycle.mjs` รันใน process แยกโดยมี PromptPay recipient จำลอง จึงไม่สร้างรายการรับเงินจริงในร้าน

> หากผลลัพธ์ของเมนูใดไม่ผ่าน ให้หยุดสรุปผล แก้ไขต้นเหตุ รันทดสอบเมนูนั้นซ้ำ และบันทึกผลการทดสอบซ้ำก่อนดำเนินการเมนูถัดไป
