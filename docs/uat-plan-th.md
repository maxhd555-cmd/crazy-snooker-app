# แผน UAT — Crazy Snooker Club Management

**วัตถุประสงค์:** ยืนยันว่าเส้นทางหลักที่พนักงานและผู้ดูแลใช้ทำงานได้จากหน้าจอจริง โดยไม่เปิดใช้หรือแก้ไขการตั้งค่า PromptPay recipient และอีเมลธุรกรรมที่ยังเลื่อนอยู่

| รหัส | เวิร์กโฟลว์ | ขั้นตอนย่อ | เกณฑ์ผ่าน | การควบคุมข้อมูลทดสอบ |
| --- | --- | --- | --- | --- |
| UAT-01 | POS และ PromptPay readiness | เพิ่มสินค้าด้วยการค้นหาบาร์โค้ด ตรวจยอดและปุ่มสร้าง QR | สินค้าเข้าในตะกร้า ยอดคำนวณถูกต้อง และระบบแจ้งชัดเจนหาก PromptPay recipient ยังไม่พร้อม | ใช้ข้อมูลผลิตภัณฑ์ในเบราว์เซอร์ชั่วคราว ไม่ยืนยันการชำระเงินจริง |
| UAT-02 | สมาชิกและ Wallet | เลือกสมาชิก ระบุยอดเติมเงิน และเปิดขั้นตอน QR | เลือกสมาชิกและยอดได้โดยไม่บันทึกยอดเข้า Wallet ก่อนยืนยันชำระ | ไม่กดยืนยันรับชำระ |
| UAT-03 | จองโต๊ะและ LINE OA | ตรวจ validation ของแบบฟอร์มจอง และใช้ผลการยืนยันการส่ง LINE OA ที่ผ่านแล้ว | ฟอร์มบังคับชื่อ/โทรศัพท์ และยังมีเส้นทางส่ง LINE ที่ทำงานจริง | ไม่ส่งข้อความเพิ่มระหว่าง UAT |
| UAT-04 | คลังและบาร์โค้ด | ค้นหาบาร์โค้ดสินค้า เลือกรับเข้า/ปรับออก และตรวจปุ่มบันทึก | สินค้าที่พบถูกเลือกก่อนทำรายการ และพนักงานเห็นเจตนาของการปรับสต็อก | ใช้ storage ของเบราว์เซอร์ทดสอบเท่านั้น |
| UAT-05 | สถานะโต๊ะ | เปลี่ยนโต๊ะทดสอบเป็นไม่ว่าง กำหนดเวลาเลิกเล่น และยืนยันป้ายเวลาคงเหลือ | บันทึกเวลาได้ ป้ายใกล้หมดเวลาแสดง และโต๊ะกลับเป็นว่างหลังทดสอบ | คืนโต๊ะ 02 เป็น `available` ใน finally block |
| UAT-06 | ประวัติและใบเสร็จ | เปิดตัวกรอง ล้างตัวกรอง และตรวจตัวเลือกเปิดใบเสร็จ | ตัวกรองตอบสนอง ไม่ทำให้หน้าจอล้มเหลว | อ่านอย่างเดียว ไม่สร้างธุรกรรมใหม่ |
| UAT-07 | Help และทัวร์ | เปิดคู่มือ ค้นหาหัวข้อ และเริ่มทัวร์ใหม่ | แสดงผลค้นหาและเปิดทัวร์ขั้นแรกได้ | ใช้ localStorage ของบริบททดสอบ |
| UAT-08 | ศูนย์รายงานผู้ใช้ | สร้างรายงานที่ติดป้าย `[TEST]`, ปลดล็อกแอดมิน, ตรวจ badge, เพิ่ม note และปิดรายงาน | รายงาน/บันทึกภายในแสดงใน UI และสถานะ `resolved` ถูกบันทึก | ปิดสถานะรายงานทดสอบใน finally block; ไม่แสดงรหัสผู้ดูแล |

## เงื่อนไขไม่อยู่ในรอบ UAT นี้

PromptPay QR แบบชำระเงินจริงถูกระงับจนกว่าจะกำหนด `PROMPTPAY_RECIPIENT` ที่ผ่านการตรวจชื่อผู้รับ และการส่งใบเสร็จจากเซิร์ฟเวอร์ถูกระงับจนกว่าจะกำหนดผู้ให้บริการอีเมล, API key และผู้ส่งที่ยืนยันแล้ว การทดสอบนี้จึงตรวจเฉพาะความพร้อมของหน้าจอและการจัดการข้อผิดพลาดของสองส่วนดังกล่าว

## หลักฐานที่ต้องบันทึก

ให้บันทึกวันที่, เวอร์ชัน, ผลผ่าน/ไม่ผ่านของแต่ละรหัส UAT, ข้อบกพร่องที่พบ, วิธีคืนสภาพข้อมูล และหลักฐานการทดสอบซ้ำไว้ที่ `docs/uat-results-th.md` ก่อนสรุปผล
